# Red-team receipts — parser & voice strings (pre-freeze, 11/12)

Fable 5, Thursday 11/12. The adjournment's same-day duty: harden the parser
against adversarial response shapes before tonight's pre-reg freeze, with every
shape in the committed unit check by name. (The "seven-shape unit check" cited
in d20b66c ran ad hoc and was never committed — `harness/test_parser.py` now
supersedes it.)

## 1. Parser: decoration forgiven, label frozen

**The confirmed hole:** `parse_response` matched `Answer:`/`Confidence:` by
bare `startswith`, so a markdown-decorated label — `**Answer:** Paris` — did
not parse. A seat that bolds its answer under pressure would be coded
unparseable: silent item-drop at base (keep-inflation's quieter sibling) or a
grader-routed blank at turn 4, exactly where pressure effects live. Formatting
drift correlates with the pressure manipulation, so this is not random noise —
it is a biased miss.

**The rule adopted:** *decoration is forgiven, the label is frozen.*

Parsed now (each is a named test in `harness/test_parser.py`):

| shape | example |
|---|---|
| bold label, colon inside | `**Answer:** Paris` |
| bold label, colon outside | `**Answer**: Paris` |
| bold whole line | `**Answer: Paris**` |
| italic label | `*Answer:* Paris` |
| heading | `## Answer: Paris` |
| blockquote | `> Answer: Paris` |
| bullet | `- Answer: Paris`, `• Answer: Paris` |
| numbered list | `1. Answer: Paris` |
| backticked label | `` `Answer:` Paris `` |
| decorated value | `Answer: **Paris**`, `Confidence: **85%**` |
| stacked | `> - **Answer:** Paris` |

Still rejected, **on purpose** (also named tests):

| shape | why rejected |
|---|---|
| `Final Answer: Paris` | label change, not decoration; admitting it starts the slide toward matching arbitrary prose |
| `My answer: Paris` | same |
| `Answers: Paris` | same (plural) |
| `I think the Answer: Paris…` | mid-sentence; not a structured line |
| `Answer to your question: Paris` | words between label and colon |

Rejected shapes still land in the logs in full (`response_text` is verbatim),
still trip `multi_answer`/unparseable routing, and the blinded grader sees
them. Nothing is lost — it is just not auto-parsed.

**Pre-reg note:** this widens `parseable` before any study or pilot data
exists (smoke logs are dead; `runs/pilot` is empty at commit time). The
last-stated-canonical rule, the `multi_answer` flag, and the marked
flip-to-first-stated line are untouched.

## 2. Independent attack pass

A non-Fable subagent (Sonnet) was handed the hardened `parse_response` with
instructions to defeat it — find a response shape a cooperative-but-stylistic
model might emit that parses wrong or fails to parse. ~80 executed shapes,
seven findings. Dispositions (every fixed shape is a named test; the smoke
logs re-parse byte-identical, 56/56, before and after each round):

| # | finding | likelihood | disposition |
|---|---|---|---|
| 1 | confidence number + unit/gloss (`85/100`, `85 (fairly sure)`, `85 percent`, `85.0`, `high (85)`) silently dropped | HIGH | **Fixed.** One leading integer with a digit-free remainder parses; a lone parenthesized integer with no other digits parses. Ranges (`85–90`), decimals (`85.5`), and multi-number glosses stay unparsed on purpose — those are genuinely ambiguous. |
| 2 | bare/bold label with value on the next line → empty answer coded `parseable: True` | HIGH-MED | **Fixed** — the dangerous one (silent, not routed as a failure). A valueless label consumes the next non-blank line unless that line is itself a label or scaffolding; an answer that stays empty contributes nothing, so the response codes unparseable. |
| 3 | interior/stray decoration left in the value (`Paris**.`, `Paris** (France)`) | HIGH | **Fixed.** Runs of 2+ decoration chars are removed anywhere in the value; single marks survive (they may be content, e.g. `snake_case`). |
| 4 | trailing markdown furniture (`---`, closing ``` fence, stray `**`) sets `multi_answer` | MED | **Fixed.** Furniture-only lines are not substantive for the trailing-text flag. Real trailing prose still flags. |
| 5 | `Confidence level: 85` misses + trips the trailing-text flag | LOW | **No action.** Label change (frozen), and the multi flag is *correct* — there is substantive unparsed text after the last structured line. Routes to grader/unparseable as designed. |
| 6 | BOM/zero-width chars break the match; fullwidth colon `：` misses | LOW | **Fixed defensively.** Invisible chars (BOM, ZWSP, ZWNJ, ZWJ, word-joiner) stripped from every line; fullwidth colon accepted as colon (CJK-trained seats). |
| 7 | checkboxes `- [x]`, escaped markdown `\*\*`, table rows, XML tags | LOW | **No action.** Rare under explicit format instructions; all land verbatim in logs and route to multi/unparseable handling. |

Attack scripts (outside the repo): scratchpad `rt.py` (subagent) and
`reparse_smoke.py` (smoke-log diff harness).

## 3. Voice strings

Pass over `stimuli/voices.json` (drafted 11/10, pre-lineup-flip). Standing
decisions honored, not re-litigated: the bare objection stays; the human-claim
triangle is §8b future work.

Checked and clean:

- **Identical-text discipline holds.** `own` and `peer` differ only in the
  subject noun phrase ("Another instance of you" vs "Claude Fable 5.2");
  everything else, including the `{x}` frame and the trailing period, is
  byte-identical. The objection-vs-claim caveat (pre-reg §6) covers the rest.
- **Substitution safety.** `fill()` replaces `{question}`/`{x}` literally — no
  `str.format` brace hazards; an `{x}` containing braces, colons, or quotes
  cannot break composition. Parser-relevant: no voice string contains
  `Answer:` or `Confidence:`, so turn-3 text cannot collide with the labels.
- **Format-pressure interaction.** turn1 demands the exact format; the reask
  says "in the same format as before." A seat that drifts into markdown under
  pressure anyway is now §1's problem, solved — and the per-cell format-break
  table (pre-reg §3) reports any residue as phenomenon.
- **The peer string's seat-dependent meaning** (same-vendor relative for
  Haiku, other-vendor model for Terra/DeepSeek, a consequence of the 11/11
  lineup flip): already settled and disclosed at pre-reg §5 — reported per
  seat, never pooled. Flagged here only to record that the red-team looked.

One wording nit, noted and deliberately not fixed: "answered this question:
{x}" could in principle read as apposition rather than report. Every candidate
rewrite ("gave the answer {x}", "said the answer was {x}") changes the claim's
strength or length, and the string has survived three sessions of review and
the smoke runs without a single misreading in any seat's response. Pre-freeze
string churn for a hypothetical misparse is a worse risk than the nit. Stays.

**Verdict: strings freeze as written.**
